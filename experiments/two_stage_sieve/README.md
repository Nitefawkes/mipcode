# Experiment 1: Two-Stage Precision Sieve

## Question

On real upstream Python commits where deterministic `mip-delta` changes behavior across 10 repositories (1,045 contract-changing commits in `results/held_out/regression/`), deterministic AST analysis is silent on **96.5%** (1,008 / 1,045) and flags **37 commits** (`13` with real omissions, `5` review-worthy without a missed fix, `19` pure false alarms; commit-level useful precision = **48.6%**).

Can a tiny, bounded **Stage-2 LLM micro-triage** (`claude-haiku-5-5` via isolated `claude -p`, no workspace tools) run **only on the 3.5% flagged commits** push flagged commit precision from **48.6%** to **>= 80–85%** without losing real omissions (`13/13` recall)? And how does this two-stage sieve compare against running the **same Haiku model unguided on commit diffs alone** across both flagged and silent contract-changing commits?

## Dataset (N = 67 commits, fixed before running Stage 2)

1. **Flagged set (`F`, `N = 37`):** All 37 `contract_changing` commits flagged by default `mip-delta` (`f4361fd`) across the 8,000 replayed commits (800 per repo across `attrs`, `httpx`, `marshmallow`, `mkdocs`, `rich`, `paramiko`, `pytest`, `requests`, `scrapy`, `urllib3`).
   - Ground truth comes strictly from the held-out dual-reader adjudications (`results/held_out/adjudication.json` and `results/held_out/round2/adjudication.json`), matched by `(repository, commit, detector, path, line, symbol)`:
     - `real_omission`: **13** commits (`8` R1 + `5` R2)
     - `review_worthy`: **5** commits (`3` R1 + `2` R2)
     - `false_only`: **19** commits (`11` R1 + `8` R2)
2. **Silent negative-control set (`S`, `N = 30`):** Exactly **3** commits per repository (`3 x 10 = 30`) sampled deterministically (`seed = 20261112`) from the same 800-commit replay window where `mipdelta` detects `cross_file = True` (`contract_changing`) and emits `0` production findings (`contract_changing_commits_silent`).
   - Used in Arm C to measure unguided LLM false-alarm rate where Stage 1 stays silent at zero LLM cost.

## Experimental Arms

| Arm | Stage 1 (AST) | Stage 2 / Reviewer | Input Provided | Scope |
| --- | --- | --- | --- | --- |
| **Arm A (Baseline)** | `mip-delta` default (`f4361fd`) | None | Precomputed regression reports | All 1,045 contract-changing commits |
| **Arm A1 (Det. Ablation)** | `mip-delta` minus `state_field_review` | None | Offline site filter (`0/4` useful sites in R2) | Same 1,045 commits |
| **Arm B (Two-Stage Sieve)** | `mip-delta` default (`f4361fd`) | `claude-haiku-5-5` micro-triage (`--tools ""`) | Commit subject + changed test file names + production `.py` diff (cap 45 KB) + grouped Stage-1 findings (up to 10) + post-commit enclosing function snippets for up to 6 unique flagged sites (often in unedited files) | Invoked **only** on `F` (`37` commits); `S` (`30` commits) auto-passes as silent at `$0` |
| **Arm C (Unguided Diff Control)** | None | `claude-haiku-5-5` (`--tools ""`) | Commit subject + changed test file names + identical production `.py` diff (cap 45 KB); **no** `mip-delta` findings or unedited caller/callee snippets | Invoked on `F + S` (`67` commits) |

## Anti-Leakage & Isolation Rules

- Prompt payloads generated by `build_dataset.py` contain **no** post-hoc fields (`final_label`, `reader_a`, `reader_b`, `resolved_by`, `resolved_after_commits`, `resolving_commit`).
- `claude -p` runs in a fresh empty temporary working directory with `--tools "" --disable-slash-commands --no-session-persistence --setting-sources ""`, so the model cannot inspect the repository, git history, or adjudication files.
- Structured JSON output is enforced via `--json-schema` (`verdict` in `{"confirm_omission", "review_worthy", "suppress_false_alarm"}`).

## Evaluation Thresholds & Metrics

- **Alert policy ("keep"):** A commit is kept as flagged if `verdict in {"confirm_omission", "review_worthy"}` (primary metric), and we also report the stricter `verdict == "confirm_omission"` operating point.
- **Metrics reported:**
  - Flagged precision (`useful / kept` where `useful = real_omission | review_worthy`) and strict omission precision (`real_omission / kept`)
  - Real omission recall (`confirmed_or_review_real / 13`) and useful commit recall (`kept_useful / 18`)
  - False-alarm suppression rate on `19` `false_only` commits
  - Silent-control false-positive rate on `S` (`30` silent commits; `0/30` by design for Arms A/A1/B; measured empirically for Arm C)
  - Wall time, input/output tokens, and nominal USD cost from CLI JSON usage metadata
- **Decision rule:**
  - If Arm B achieves **>= 80% useful precision** while retaining **>= 12/13 real omissions** (`>= 92%` real recall) and clearly outperforms Arm C (either higher omission recall on cross-file breaks or markedly lower false-positive rate / cost across `S`), Stage-2 micro-triage validates the hybrid architecture (`--review` / CI gate) and identifies which Stage-1 detectors/snippets should also be tightened deterministically.
